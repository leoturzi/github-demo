Tema 7 · Seguridad, ecosistema y cierre

Buenas prácticas y quiz final

Checklist

Activar 2FA en tu cuenta▸

2FA (autenticación en dos pasos) pide un segundo código, además de la contraseña: una app en el celular, una llave física o un SMS. Si te roban la contraseña, igual no pueden entrar. GitHub la recomienda y en muchos casos la exige.

Nunca subir contraseñas ni tokens (.gitignore)▸

Los secretos (contraseñas, claves de API, tokens) nunca van al repo: queda en la historia aunque después lo borres. El archivo .gitignore lista lo que Git debe ignorar, como .env o node_modules/. Si algo se filtra, hay que cambiar la clave.

Activar Dependabot para dependencias▸

Dependabot revisa las librerías que usa tu proyecto. Si alguna tiene una vulnerabilidad conocida, te avisa y abre un Pull Request automático con la versión corregida.

Commits chicos y con mensajes claros▸

Un commit = una idea. Mensajes como agrego login con Google y no cambios. Así el historial se lee como un diario y es fácil encontrar o deshacer un cambio puntual.

Proteger main y usar Pull Requests▸

Las branch protection rules bloquean los push directos a main: todo cambio entra por Pull Request, con al menos una revisión aprobada. Evita errores y mantiene main siempre estable.
